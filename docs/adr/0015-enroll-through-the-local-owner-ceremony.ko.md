# 0015 로컬 소유자 절차로 등록한다

> 이 문서는 [0015-enroll-through-the-local-owner-ceremony.md](0015-enroll-through-the-local-owner-ceremony.md)의 한국어 읽기본입니다. 기준은 영어 원문입니다.
> 원문 해시: `sha256:5ffb2b0e8b2e292bd8ef07e1f59a35fcccbc559bae1ad8462eb2faaef2258f13`. 영어 원문이 바뀌면 `scripts/tests/test_reading_copies.py`가 실패합니다.

상태: 승인됨(Accepted). 2026-11-20, PR #7 설계 검토.

## 배경

소유자와 에이전트는 운영체제 계정을 함께 씁니다. 위협 모델 A에서 에이전트는 작업 데이터에 주입된 지시가 있어도 규칙을 따릅니다.
사람 터미널 규칙은 이미 로컬 서명을 소유자에게만 맡깁니다. 에이전트는 이 규칙을 이용해 소유자를 흉내 내지 않습니다. [사람 신원](../../skills/graph-flow/SKILL.md#human-identity) · [터미널 검사](../../skills/graph-flow/scripts/graphflow/cli.py)

표시된 두 값을 비교하는 방식에서는 후보 기기의 값을 하나도 입력하지 않고 승인할 수 있었습니다.

## 결정

첫 등록, 기기 추가, 교체, 복구에는 관리자 권한 없이 POSIX 호스트에서 로컬 소유자 절차를 씁니다.
`GF_ROLE=human`, `GF_HUMAN_TERMINAL=1`, 표준 입력의 로컬 TTY가 필요합니다.
에이전트는 이 절차를 실행하지 않고, 등록 코드, 역방향 코드, 절차 출력을 읽거나, 전달하거나, 사용하지 않습니다.

1. 로컬 소유자 절차를 시작하고 작업을 고릅니다.
2. 절차가 보여 주는 일회용 등록 코드를 읽습니다. 코드에는 40비트 이상의 무작위 값이 들어 있고, 5분 안에 만료됩니다.
3. 후보 기기에서 설정된 HTTPS 오리진에 접속해 그 코드를 입력합니다.
4. 원격 화면이 코드를 원자적으로 소비하고, 요청을 후보 세션 하나에 예약합니다.
5. 후보 기기가 새 패스키를 등록하고, 새 어설션으로 그 패스키를 가지고 있음을 증명합니다.
6. 후보 기기가 RA-R4에 따라 그 요청과 증명된 자격 증명에서 만든 역방향 코드를 보여 줍니다.
7. 절차 터미널에서 코드 사용 시각과 클라이언트 사용자 에이전트를 읽습니다.
8. 원래 요청이 만료되기 전에 후보 기기의 역방향 코드를 그 터미널에 입력합니다.

터미널은 예상 역방향 코드를 보여 주지 않습니다. 역방향 코드는 base32 문자 8개 이상이고, 키를 쓴 출력을 40비트 이상 담습니다.
비교에 성공한 자격 증명만 정확히 활성화합니다.
코드 사용과 역방향 코드 입력은 같은 설치본 전체 등록 한도에서 차감합니다. 만료되거나, 재사용되거나, 바꿔치기된 자격 증명은 버립니다.
두 코드는 로그, URL, 프로젝트 파일, 에이전트가 볼 수 있는 출력에 남기지 않습니다.
교체 기기를 활성화하기 전에 잃어버린 기기의 권한을 회수합니다. 이전 귀속 기록과 실행 키 고정 정보는 남깁니다.
등록부가 없으면 어떤 기기도 허가하지 않습니다. 등록부를 잃으면 로컬 복구를 요구합니다.
사용 동의는 로컬에 둡니다. RA-R8에 따른 최소한의 원격 기기 목록과 대상을 정한 권한 회수는 허용합니다.

## 검토한 대안

첫 등록을 자동으로 하면 원격 방문자가 빈 설치본을 차지할 수 있습니다. 로컬 대시보드 토큰에는 등록 권한이 없습니다.
서명과 등록을 모두 별도 운영체제 주체로 옮기면 같은 계정의 적대적인 쓰기를 막을 수 있습니다. 이 강화는 향후 과제입니다.

## 결과

소유자는 등록된 기기를 모두 잃어도 로컬에서 복구할 수 있습니다. 지원되는 에이전트 인터페이스는 답변, 등록, 권한 회수, 복구 권한을 주지 않습니다.
이 보호 수준은 로컬 서명기와 같습니다. 공유 계정은 `human.key`를 읽을 수 있습니다.
그 계정을 가진 적대적인 프로세스는 코드나 등록부 파일을 고쳐 이 절차를 우회할 수 있습니다.
