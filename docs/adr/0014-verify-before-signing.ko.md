# 0014 서명 전에 원격 답변마다 검증한다

> 이 문서는 [0014-verify-before-signing.md](0014-verify-before-signing.md)의 한국어 읽기본입니다. 기준은 영어 원문입니다.
> 원문 해시: `sha256:c04ddc8cbf1796575596c722372ce30c386ff9e1c5f919f73ccfafc72122b526`. 영어 원문이 바뀌면 `scripts/tests/test_reading_copies.py`가 실패합니다.

상태: 제안됨(Proposed)

## 배경

로컬 대시보드는 표시된 식별 정보를 기존 답변 트랜잭션에 넘깁니다.
트랜잭션은 서명하기 전에 질문과 증거를 검사합니다. HMAC v3는 이미 결과와 정확한 답변 글을 묶습니다.
읽기 세션만으로는 소유자가 표시된 답변을 골랐다는 증거가 되지 않습니다. [결정](../../skills/graph-flow/scripts/graphflow/decisions.py) · [코어](../../skills/graph-flow/scripts/graphflow/core.py)

## 결정

원격 답변마다 사용자 확인이 포함된 WebAuthn 패스키를 씁니다.
소유자가 결과를 고르면 최종 선택과 답변 글을 보여 줍니다.
RA-R5의 전체 맥락에 대해 답변 확인 요청을 발급합니다. 내용을 고치면 그 확인 요청은 버립니다.
새 어설션을 저장된 맥락과 대조해 검증합니다. 동시 요청 사이에서도 확인 요청은 한 번만 소비합니다.
기존 답변 트랜잭션이 커밋될 때까지 기기 권한을 다시 확인합니다. 트랜잭션이 거부하면 새 확인 요청을 요구합니다.
기존 서명 입력, source, 검증기, 게이트 규칙은 그대로 둡니다. [RA-R5](../spec/remote-approval.ko.md#ra-r5--답변마다-인증하기) · [RA-R6](../spec/remote-approval.ko.md#ra-r6--실행-답변-계약-지키기)

Python 표준 라이브러리만 쓰는, 프로젝트가 소유한 검증기를 씁니다. 첫 프로필은 P-256 위의 ES256으로 제한합니다.
증명(attestation) 형식은 `none`과 비어 있는 증명 내용만 받아들입니다.
등록마다 소유자 한 명이 허가합니다. 검증기는 새 어설션으로 패스키를 가지고 있는지 확인합니다. 여기서는 하드웨어 출처 정보로 권한을 판단하지 않습니다.
RA-R12의 한도가 있는 CBOR 파서, 프로토콜 검사, 비밀 값 비교를 요구합니다.
릴리스에서 원격 답변을 켜기 전에 정확한 검증기 버전을 공개 벡터로 확인하고, 독립된 암호 검토를 받습니다. [RA-R12](../spec/remote-approval.ko.md#ra-r12--패스키-프로필-검증하기) · [RA-R13](../spec/remote-approval.ko.md#ra-r13--릴리스-전에-검증기-자격-확인하기)

명시적인 지도 확인에도 같은 실행 안 답변 경로를 씁니다. [RA-R7](../spec/remote-approval.ko.md#ra-r7--지도-확인-권한-제한하기) · [ADR 0017](0017-confirm-out-of-run-items-in-the-next-run.ko.md)

## 검토한 대안

로그인할 때만 검증하면 훔친 읽기 세션으로 다른 질문에 답할 수 있습니다. 일회용 비밀번호는 실시간 중계 공격을 허용합니다.
외부 암호 라이브러리를 쓰면 의존성 예외가 필요합니다. HMAC v3를 바꾸면 등록 문제는 풀지 못하면서 기존 검증기에 영향을 줍니다.

## 결과

소유자는 등록된 기기에서 답변마다 확인합니다. 인증기는 challenge에 서명하고, 답변을 보여 주는 일은 브라우저에 맡깁니다.
프로젝트가 보안에 중요한 파싱과 서명 검증을 유지보수합니다. 원격 답변을 쓰려면 배포된 검증기에 대한 검토 증거가 필요합니다.
로컬 서명 키를 읽을 수 있는 계정은 원격 검사를 우회할 수 있습니다.
